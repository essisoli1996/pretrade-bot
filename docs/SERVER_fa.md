# راه‌اندازی سرور ربات pretrade روی Oracle Cloud

ربات تا امروز روی GitHub Actions اجرا می‌شد. این راهنما آن را به یک سرور رایگان Oracle منتقل می‌کند.
کارهایی که فقط خودت می‌توانی بکنی **۴ مرحله** است، بقیه خودکار است.

## مرحله ۱: ساخت حساب Oracle Cloud (حدود ۱۵ دقیقه)
1. برو به https://signup.cloud.oracle.com
2. ایمیل، کشور و اسم را وارد کن. **کارت بانکی بین‌المللی** لازم است (فقط برای تأیید هویت؛ تا از منابع رایگان بیرون نزنی چیزی کم نمی‌شود).
3. **Home Region** را با دقت انتخاب کن؛ بعداً عوض نمی‌شود. یک منطقه‌ی نزدیک و کم‌شلوغ مثل `Germany Central (Frankfurt)` یا `UK South (London)` خوب است.
4. بعد از ورود، پیشنهاد می‌کنم حساب را به **Pay As You Go** ارتقا بدهی (منوی Billing → Upgrade). هنوز رایگان است ولی Oracle ماشین‌های رایگانِ «بیکار» حساب‌های رایگان را پس می‌گیرد؛ ربات ما پردازش کمی دارد و ممکن است «بیکار» حساب شود. با Pay As You Go این اتفاق نمی‌افتد.
   - برای اطمینان: در Billing → Budgets یک بودجه‌ی ۱ دلاری با هشدار ایمیلی بساز.

## مرحله ۲: ساخت کلید SSH (۲ دقیقه)
روی کامپیوتر خودت (ویندوز: PowerShell، مک/لینوکس: Terminal):
```
ssh-keygen -t ed25519 -f pretrade_server -N ""
```
دو فایل ساخته می‌شود:
- `pretrade_server.pub` ← **کلید عمومی** (در مرحله ۳ به Oracle می‌دهی)
- `pretrade_server` ← **کلید خصوصی** (در مرحله ۴ به GitHub می‌دهی؛ هیچ‌جای دیگر نگذار)

## مرحله ۳: ساخت ماشین (حدود ۵ دقیقه)
در کنسول Oracle: منو → Compute → Instances → **Create instance**
- **Image**: روی Change image بزن → **Canonical Ubuntu 24.04**
- **Shape**: روی Change shape بزن → Specialty and previous generation → **VM.Standard.E2.1.Micro** (برچسب Always Free دارد)
  - اگر Ampere (VM.Standard.A1.Flex) با ۱ پردازنده و ۶ گیگ حافظه در دسترس بود، آن بهتر است؛ اگر خطای «Out of capacity» داد همان E2.1.Micro را بردار.
- **Networking**: پیش‌فرض را بپذیر، فقط مطمئن شو «Assign a public IPv4 address» روشن است.
- **Add SSH keys**: گزینه‌ی «Paste public keys» → محتوای فایل `pretrade_server.pub` را بچسبان.
- Create را بزن. وقتی وضعیت **Running** شد، **Public IP address** را یادداشت کن.

## مرحله ۴: دادن دسترسی به GitHub (۲ دقیقه)
در repo: Settings → Secrets and variables → Actions → **New repository secret**
| نام | مقدار |
|---|---|
| `SERVER_HOST` | همان Public IP |
| `SERVER_SSH_KEY` | کل محتوای فایل `pretrade_server` (کلید خصوصی، از خط BEGIN تا END) |

secretهای قبلی (MUSE_IDENTITY، BANKR_LLM_KEY، OPENROUTER_KEY) سر جایشان می‌مانند و خودکار به سرور منتقل می‌شوند. هیچ کلیدی از دست کسی رد نمی‌شود.

## از اینجا به بعد خودکار است
در repo: Actions → **server** → Run workflow:
1. `setup` → سرور را نصب می‌کند (Node، سرویس، به‌روزرسانی خودکار) و secretها را منتقل می‌کند. آخرش گزارش وضعیت می‌دهد.
2. `takeover` → ربات از GitHub به سرور منتقل می‌شود. ربات GitHub بعد از دور فعلی‌اش حافظه‌اش را ذخیره و خاموش می‌شود؛ سرور حدود ۷ دقیقه بعد همان حافظه را برمی‌دارد و شروع می‌کند. هیچ‌وقت دو ربات هم‌زمان روشن نیستند.
3. `status` → هر وقت خواستی ببینی ربات زنده است یا نه.

## کار روزمره
| می‌خواهی… | Actions → server → |
|---|---|
| ببینی ربات سالم است | `status` |
| ربات را دوباره روشن کنی | `restart` |
| کلید/توکنی عوض شد | اول secret را در GitHub عوض کن، بعد `secrets` |
| برگردی به GitHub Actions | `handback` |
| حافظه را همین الان پشتیبان بگیری | `backup` (هر ساعت خودکار هم انجام می‌شود) |

## خودکارها
- **به‌روزرسانی کد:** سرور هر ۵ دقیقه main را چک می‌کند. کد جدید فقط وقتی اجرا می‌شود که تست‌ها رد شوند؛ کد خراب هیچ‌وقت به ربات زنده نمی‌رسد.
- **کرش:** اگر ربات بیفتد، ۵ ثانیه بعد خودش بالا می‌آید. بعد از خاموش/روشن شدن سرور هم خودش شروع می‌کند.
- **پشتیبان:** حافظه‌ی ربات هر ساعت در repo ذخیره می‌شود؛ اگر سرور از بین برود، با `handback` ربات با همان حافظه روی GitHub ادامه می‌دهد.
