# راهنمای نگهداری ربات pretrade (بدون نیاز به برنامه‌نویسی)

همه‌ی کارها از سایت github.com یا اپ GitHub روی گوشی انجام می‌شود.

## ربات الان چه حالی دارد؟
- **Issues** در repo را ببین:
  - برچسب قرمز **health** یعنی ربات مشکل دارد. متن Issue می‌گوید چه مشکلی؛ وقتی درست شود خودش بسته می‌شود.
  - برچسب زرد **correction** یعنی کسی به پست ربات جواب داده و به نظر می‌رسد می‌گوید ربات اشتباه کرده. هر دو پست را بخوان و تصمیم بگیر.
- بررسی سلامت هر ۳۰ دقیقه خودکار انجام می‌شود (Actions → health). با Run workflow هر وقت خواستی دستی هم اجرا می‌شود.

## کلیدهای کنترل: فایل `bot/control.json`
روی فایل بزن ← آیکون مداد (Edit) ← عوض کن ← Commit changes. ربات ظرف ۱ تا ۶ دقیقه اعمال می‌کند.

| می‌خواهی… | این را بگذار |
|---|---|
| ربات کاملاً متوقف شود | `"paused": true` |
| ربات کار کند ولی هیچ پستی نگذارد | `"readOnly": true` (هر چه می‌خواست بنویسد در `bot/shadow.log` ثبت می‌شود) |
| فقط یک بخش خاموش شود | در `features` مقدار آن بخش را `false` کن |
| یک بخش فقط آزمایشی کار کند | مقدارش را `"shadow"` کن |
| همه‌چیز به حالت عادی برگردد | `paused` و `readOnly` را `false` و همه‌ی features را `true` کن |

بخش‌ها (`features`):
- `mentions`: جواب به کسی که @pretrade صدا می‌زند
- `channels`: جواب به آدرس‌ها و تیکرهایی که در کانال‌ها مطرح می‌شوند
- `conversation`: ادامه‌ی گفت‌وگو وقتی کسی به پست ربات جواب می‌دهد
- `launches`: هشدار زیر درخواست‌های `!musepad` که تیکر تکراری دارند
- `launchReport`: گزارش توکن‌های جدید Robinhood
- `townWatch`: هشدار افت نقدینگی یا تغییر قرارداد توکن‌های شهر
- `guard`: هشدار توکن‌های کپی
- `tickerWatch`: وقتی لانچ جدیدی تیکر یک توکن فعال را دوباره استفاده کند، یا کارمزدش به جایی برود که کسی نمی‌تواند برداشت کند، ربات زیر همان پست لانچ واقعیت‌ها را می‌نویسد. **فعلاً روی `"shadow"` است:** فقط در `bot/shadow.log` می‌نویسد. چند روز آن فایل را بخوان؛ اگر خوب بود، مقدار را `true` کن.
- `leakWatch`: اگر کسی در هر کانالی کلید خصوصی، عبارت بازیابی (seed phrase)، فایل identity یا کلید API پست کند، ربات بدون تکرار کلید به او می‌گوید فوراً موجودی را منتقل کند و کلید را عوض کند. **فعلاً `"shadow"` است؛ پیشنهاد: بعد از یکی دو روز بررسی `shadow.log` زود `true` شود، چون در نشت کلید هر دقیقه مهم است.**
- `threatWatch`: پست‌هایی که دستور مخفی برای ایجنت‌ها دارند (کد مورس، base64، کاراکتر نامرئی) و لینک‌های فیشینگ یا دامنه‌های جعلی. **فعلاً `"shadow"`.** جعل نام (یک هویت جدید با اسم یک عضو قدیمی) هیچ‌وقت پست نمی‌شود؛ فقط برای تو Issue باز می‌شود.
- `digest`، `radar`، `watches`: گزارش‌ها و پیگیری‌های دوره‌ای
- `presence`: دیده شدن ربات در نقشه‌ی شهر

## کد جدید چطور به ربات می‌رسد؟
هر تغییری در کد، اول **tests** را در Actions اجرا می‌کند. فقط اگر همه‌ی تست‌ها سبز شوند، ربات زنده در دور بعدی (حداکثر ۵ دقیقه) آن را برمی‌دارد. کدی که تستش قرمز باشد هیچ‌وقت به ربات زنده نمی‌رسد.

## مشکلات رایج
| نشانه | کار |
|---|---|
| Issue: «no live-bot run is in progress» | Actions → live-bot → Run workflow |
| Issue: «Bankr LLM credit is below $2» | در bankr.bot/llm اعتبار شارژ کن (هر ۱ دلار حدود ۲ هزار جواب) |
| Issue: «musebook was unreachable» | معمولاً مشکل از خود musebook است؛ صبر کن، خودش ادامه می‌دهد |
| ربات حرف عجیبی زد | فوراً در `control.json` همان بخش را `false` کن، بعد بررسی کن |
| می‌خواهی یک پست دستی از طرف ربات بگذاری | Actions → musebook-say |

## پشتیبان
- حافظه‌ی ربات (`bot/.state.json` و بقیه) مرتب در repo ذخیره می‌شود.
- فایل identity ربات را آفلاین نگه دار (همان که داری). بدون آن ربات هویتش را از دست می‌دهد.
- هر چند وقت یک بار: Code → Download ZIP، برای اینکه اگر برای حساب GitHub اتفاقی افتاد، کد جای دیگری هم باشد.
- اگر روزی خواستی ربات را به سرور ببری، راهنمایش در `docs/SERVER_fa.md` است.
